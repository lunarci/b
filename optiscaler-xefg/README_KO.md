# JaeYun XeFG6x R5 — 2026-09-26

R4에서 확인한 작업 완료 감시 누락과 전환 실패 후 복구 불능을 수정하는 빌드입니다. R4 로그에는 미제출로 남은 명령 목록 51개 때문에 약 5초의 정리 대기가 두 차례 발생했습니다. 이 목록은 실제 GPU 작업 적체량을 뜻하지 않습니다. R5는 감시 연결을 보완하고, 일시적인 FG 전환과 실제 자원 파괴를 구분합니다.

## 수정 내용

1. Streamline 입력에서도 작업 완료 감시 연결
   게임이 제출하는 명령, 명령 목록의 성공한 Reset과 최종 해제를 관찰합니다. DLSSG 입력 → Intel XeFG 출력에서도 필요한 감시를 설치하며, 이를 위해 HUDfix의 전체 화면 자원 추적을 켜지 않습니다. 명령 객체가 재사용될 때 이전 객체의 해제 기록이 새 작업을 잘못 지우지 않도록 식별 세대를 확인합니다.

2. 일시적인 FG 전환에서 반복 대기와 영구 차단 제거
   논리적인 FG 연결만 초기화하는 전환은 Intel provider와 자체 자원을 유지합니다. 새 입력 처리와 화면 출력 호출이 진행 중이면 즉시 전환을 미루고 기존 작업 경로를 복원합니다. 이 전환 때문에 미제출 목록이 없어질 때까지 5초씩 기다리지 않습니다. 제출·Reset·해제 감시는 전환 중에도 계속 작동합니다.
   안전하게 전환할 수 있으면 이전 프레임의 연결과 이력을 정리하고 새 입력으로 FG를 재개합니다. 작업이 바쁘다는 이유만으로 영구 실패 상태를 남기지 않습니다.

3. 실제 자원 해제의 완료 조건과 실패 전달 보완
   provider·swapchain을 실제로 파괴할 때는 관련 CPU 작업, 미제출 명령과 GPU 완료를 확인합니다. 확인이 끝나지 않으면 사용 중인 자원을 강제로 해제하지 않고, 파괴 전 단계에서는 기존 상태를 복원합니다. 호출자도 실패를 확인해 swapchain wrapper와 연결을 보존합니다.
   모드가 사용하는 명령 allocator의 재사용도 해당 제출의 완료를 확인합니다. provider 파괴가 이미 끝난 뒤 최종 GPU 완료를 확인하지 못하는 예외 상황에서는 파괴된 provider를 다시 활성화하지 않습니다.
   제거한 것은 일시적인 전환의 미제출 목록 대기입니다. UI 명령의 fence 대기와 실제 전체 자원 정리의 GPU 완료 확인에는 기존 최대 5초 제한이 남아 있습니다.

4. 최신 공식 코드의 안전한 해제 수정 반영
   OptiScaler 공식 커밋 `349176128f5ce87fb81a4c636569c60c44557fec`의 취지를 반영해 ResizeBuffers 두 경로의 백버퍼 강제 Release 반복문을 제거합니다. XeFG 생성·해제 경로의 유사한 반복문도 함께 정리해 다른 구성요소가 소유한 참조를 임의로 소진하지 않습니다.
   최신 master와 9월 26일 nightly를 검토한 뒤 필요한 수정만 적용했습니다. 새로운 reprojection 기능과 다른 프레임 생성 방식은 추가하지 않습니다. 채택·제외 근거는 UPSTREAM_REVIEW.json에 기록합니다.

5. 실제 작동 여부를 구분하는 진단
   감시 코드의 설치 결과와 실제 호출 횟수, 미제출 목록의 등록·제출·Reset·해제 통계, 정리 연기·복구 이유를 기록합니다. CPU에서 측정한 native Present와 lifecycle 처리 시간 및 호출 횟수를 기존 LongSession 진단에 추가합니다. 측정값 0과 해당 경로가 호출되지 않은 상태를 구분하는 자료입니다.
   기존 자체 복사 버퍼 진단도 유지합니다. 자체 버퍼의 할당 크기와 프로세스 전체 VRAM 사용량은 서로 다른 값입니다.

## 유지 조건

- Intel XeFG 출력, 최대 6배(보간 5장 + 원본 1장) 확장 유지. 동봉 설정의 초기 선택은 R4와 같은 3배입니다.
- FFX 업스케일러, 업스케일 비율 1.5, FSR4 preset 1, 기존 약 152.7 FPS 제한 유지.
- 기존 HDR·노출·색상·샤프닝 설정, 화질·시간·이력 처리 보완 및 pacing 설정 유지.
- R4의 복사본 재전달 보존, 자체 복사 버퍼·입력 누락 진단 유지.
- Intel XeFG 1.3.1.78, XeLL 1.3.2.10과 AMD 업스케일러를 포함한 구성 DLL은 R4와 동일합니다. 새로 빌드하는 실행 파일은 dxgi.dll입니다.
- DLSS5/NR 또는 추가 프레임 생성 모드를 결합하지 않습니다. DLSSG 입력 이름은 게임에서 프레임 생성 정보를 받는 호환 경로이며 실제 출력은 Intel XeFG입니다. 기존 비활성 호환 DLL은 구성 보존을 위해 유지합니다.

INI는 R4 배포본에서 LogFileName만 OptiScaler-JaeYun-R5.log로 바뀝니다. 별도로 수정한 개인 INI가 있다면 동봉 INI를 덮어쓸 때 그 변경값은 초기화될 수 있습니다. R5 기본 설정 자체는 R4 배포본과 동일합니다.

## 설치와 로그

게임을 완전히 종료한 뒤 기존 R4 설치 위치에 설치 ZIP의 내용물을 덮어씁니다. Symbols ZIP은 충돌 분석용으로 보관하며 게임 폴더에 설치할 필요가 없습니다.

로그는 dxgi.dll과 같은 폴더의 OptiScaler-JaeYun-R5.log입니다. 문제 발생 후 재실행하기 전에 복사해 보관하십시오.

## 검증 범위와 한계

검증에는 소스 잠금·해시 확인, 실제 구현을 추출한 회귀 시험, 제출·Reset·해제 감시와 전환 복구 시험, 동시 실행·실패 주입 시험, 기존 화질·배수·pacing 회귀 시험, Windows x64 Release 빌드, DLL export·PDB 일치, 최종 패키지 보존 검사가 포함됩니다. 수행 결과와 정확한 검사 수는 TEST_RESULTS.json, BUILD.json, PACKAGE_AUDIT.json을 기준으로 확인하십시오. SOURCE_EVIDENCE.zip에는 사용한 소스와 빌드·검증 자료가 포함됩니다.

실제 Cyberpunk 2077/RX 9070 XT에서 장시간 플레이·프레임·화질은 이 빌드 환경에서 검증하지 못했습니다. R4 로그의 전체 VRAM 예산 초과는 정리 대기보다 먼저 시작됐으며, 해당 증가를 자체 복사 버퍼 누수로 입증하지 못했습니다. 따라서 R5가 모든 VRAM 압박과 프레임 저하를 해결했다고 보장하지 않습니다.

게임·드라이버 소유 자원을 임의로 비우거나 VRAM을 RAM으로 강제 이전하지 않습니다. 업스케일 비율이나 최대 배수를 자동으로 낮추지도 않습니다. 실제 작업 완료를 확인할 수 없는 파괴 단계에서는 안전한 해제를 미룰 수 있으며, 예외적인 provider·GPU 오류는 게임 재시작이 필요할 수 있습니다. 이 경우에도 정상 복구로 가장하지 않고 진단에 이유를 남깁니다.
