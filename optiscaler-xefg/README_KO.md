# JaeYun XeFG6x R8

Intel 프레임 생성 3배·4배를 주로 사용하는 환경에서, 매번 최대 6배를 기준으로 XeFG를 초기화하던 방식을 개선한 빌드입니다. 기본 초기화 용량을 4배로 두어 3배와 4배를 실행 중 전환할 수 있고, 5배·6배 선택 기능도 유지합니다. 기본 선택 배수는 기존과 같은 3배입니다.

재윤님이 확인한 도그타운의 RT 조명 사이코 설정 문제를 고려해 FG 측 메모리 부담을 줄일 가능성을 검토한 변경입니다. 초기화 인자를 줄인 것이 실제 VRAM 절약이나 사이코 설정의 FPS 회복을 보장하지는 않습니다. 실제 게임·RX 9070 XT에서 절감량과 장시간 안정성은 아직 측정하지 못했습니다.

## R7에서 달라진 점

1. 일상적으로 사용하는 3배·4배에 맞춘 초기화 용량
   새 `LowMemoryMode=true` 설정에서는 2~4배를 직접 선택한 상태로 시작할 때 SDK를 최대 4배 용량으로 초기화합니다. 3배는 원본 1장과 보간 2장, 4배는 원본 1장과 보간 3장입니다. 3배와 4배 전환은 기존의 SDK 동적 배수 변경 경로로 처리하며, 모드가 메모리 압박을 이유로 배수를 자동으로 낮추지 않습니다.

2. 선택 가능한 최대 배수와 현재 초기화 용량을 분리
   최대 6배 확장은 유지하지만, 4배 용량으로 시작한 세션에서 5배·6배를 선택하면 즉시 적용하지 않습니다. 선택한 설정을 저장하고 게임을 완전히 종료한 뒤 다시 실행해야 합니다. 그 세션의 실제 적용 배수는 유지되며, UI와 진단에는 요청한 배수와 현재 적용한 배수를 구분해 표시합니다. 현재 SDK 용량을 초과한 배수를 그대로 전달하지 않습니다.
   5배·6배를 직접 선택해 저장한 상태로 시작하면 최대 6배 용량으로 초기화하므로 해당 세션에서 5배와 6배도 전환할 수 있습니다. 4배 용량으로 다시 시작하려면 3배 또는 4배를 선택해 저장한 뒤 재실행하십시오.

3. 기존 초기화 방식으로 돌아갈 수 있는 설정
   `LowMemoryMode=false` 또는 배수 `Auto`에서는 지원 최대치로 초기화하는 기존 방식을 사용합니다. 동적 배수 변경 API가 없는 이전 SDK에서는 기존의 초기 선택 배수 동작을 유지합니다. 현재 배포하는 Intel SDK는 교체하지 않습니다.

4. 진단에서 서로 다른 배수 값을 구분
   지원 최대치, SDK 초기화 용량, 요청한 배수, 실제 적용 배수를 구분합니다. SDK가 지원하는 최대치와 이번 세션에서 준비한 용량을 같은 값으로 해석하지 않도록 했습니다. API의 보간 프레임 수는 원본 프레임을 제외한 값이므로, 보간 3장은 화면 출력 최대 4배에 해당합니다.

## 유지 조건

- Intel XeFG 출력, 최대 6배 확장 및 초기 선택 3배를 유지합니다. 자동 배수 감소는 없습니다.
- FFX 업스케일러, 업스케일 비율 1.5, FSR4 preset 1, 기존 약 152.7 FPS 제한, HDR·노출·색상·샤프닝과 pacing 설정을 유지합니다.
- Intel XeFG 1.3.1.78, XeLL 1.3.2.10 및 AMD 업스케일러 등 기존 구성 DLL을 유지합니다. 새로 빌드하는 모드 DLL은 `dxgi.dll`입니다.
- R7의 제출 세대 추적, GPU 큐 진행 관측, GPU 할당 진단과 R6·R5의 자원 수명 보호를 유지합니다.
- DLSS5/NR와 추가 FG 모드 중첩은 포함하지 않습니다. DLSSG 입력 이름은 게임 정보를 받는 호환 경로이며 실제 출력은 Intel XeFG입니다.
- 게임 RT 조명, 텍스처 품질과 엔진 INI는 변경하지 않습니다. 사이코를 울트라로 바꾸거나 간접조명을 끄는 처리를 포함하지 않습니다.
- 강제 RAM 이전, 게임 자원 강제 해제, 상주 우선순위 조작과 고정 2.5GiB 회수는 구현하지 않았습니다.
- 런타임에서 XeFG 스왑체인을 강제로 재생성하지 않습니다. 4배 용량을 초과하는 선택은 저장 후 재실행으로 반영합니다.

## 설치와 사용

게임을 완전히 종료한 뒤 기존 모드의 `dxgi.dll`이 있는 폴더에 설치 ZIP의 내용물을 덮어씁니다. Symbols ZIP은 충돌 분석용이며 설치할 필요가 없습니다. 직접 수정한 INI는 덮어쓰기 전에 보관하십시오.

동봉 INI는 R7 배포 설정을 기준으로 새 저메모리 초기화 설정과 R8 로그 이름을 적용합니다. 평소처럼 3배·4배를 번갈아 사용하는 경우 추가 조작 없이 실행 중 배수를 변경할 수 있습니다.

새 설정은 INI의 `[XeFG]` 구역에 있습니다. 기존 최대 용량 초기화로 되돌리려면 `LowMemoryMode=false`로 바꾸고 게임을 재실행하십시오.

5배·6배를 사용하려면 원하는 배수를 선택하고 OptiScaler 설정을 저장한 뒤 게임을 완전히 종료하고 다시 실행하십시오. 5배·6배를 선택만 한 상태와 실제 적용된 상태는 다를 수 있으므로 UI의 적용 배수와 재실행 안내를 확인하십시오.

로그는 `dxgi.dll`과 같은 폴더의 `OptiScaler-JaeYun-R8.log`입니다. 문제가 발생하면 게임을 다시 실행하기 전에 복사해 보관하십시오.

기존 할당 관측 기능은 INI의 아래 설정으로 시작 시 비활성화할 수 있습니다.

```ini
[Diagnostics]
GpuAllocationTracking=false
```

기본값은 `true`입니다. 이 값은 시작할 때 고정되며 게임 중 변경해도 적용되지 않습니다. Intel FG와 기존 자원 수명 추적, GPU 큐 진행 관측은 유지합니다.

## 검증 범위

기존 17개 소스 회귀 시험을 유지하고, R8의 초기화 용량·요청 배수·적용 배수 경계를 확인하는 회귀 시험을 추가합니다. 실제 생산 함수와 도우미의 동작, 실패 처리, 참조 수명, 품질 설정·셰이더 보존, Windows x64 Release 빌드와 DLL/PDB·패키지 무결성을 검증합니다. 정확한 실행 결과는 `TEST_RESULTS.json`, `BUILD.json`, `PACKAGE_AUDIT.json`, `QUALITY_REVIEW.json`, `INDEPENDENT_REVIEW.json`을 기준으로 확인하십시오. `SOURCE_EVIDENCE.zip`에는 소스와 검증 자료가 포함됩니다.

실제 Cyberpunk 2077/RX 9070 XT의 도그타운 이동과 장시간 플레이는 이 환경에서 실행하지 못했습니다. 테스트 통과는 게임의 RT 조명 사이코 문제 해결, 특정 VRAM 절감량 또는 FPS 상승을 보장하지 않습니다. 해제 패치가 적용된 Intel SDK의 내부 할당도 공개 API 초기화 값만으로 전부 계산할 수 없습니다.
