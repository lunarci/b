# JaeYun XeFG6x R7

Night City에서 Dogtown으로 이동한 뒤 프레임이 계속 낮아지는 현상을 대상으로, 제출한 명령 목록의 수명 추적 경쟁을 수정하고 메모리 증가·GPU 큐 진행·진단 자체의 CPU 비용을 구분하도록 개선한 빌드입니다. 원래 화질과 Intel 프레임 생성 설정은 유지합니다. 실제 게임에서 증상이 완전히 해결됐다는 검증은 아직 없습니다.

## R6에서 달라진 점

1. 다시 기록한 명령 목록을 이전 제출의 완료 처리에서 지우던 경쟁 수정
   `ExecuteCommandLists`가 반환한 직후 다른 스레드가 같은 명령 목록을 Reset하고 새 작업을 기록할 수 있습니다. 기존 코드는 포인터만 보고 이전 제출을 정리해 새 기록까지 목록에서 지울 수 있었습니다. R7은 제출 전에 세대 번호를 기억하고 그 범위에 포함된 기록만 정리합니다. 실제 제출과 후속 관측 동안 기존 수명 보호를 유지합니다. 소스에서 확인한 결함이지만, Dogtown 메모리 증가의 원인이었다고 입증된 것은 아닙니다.

2. CPU 제출과 GPU 큐 진행을 구분
   `[GpuProgress]`는 XeFG가 이미 추적 중인 최대 8개 큐만 관찰합니다. 실제 제출 이후 별도의 fence에 표시를 남기며, 큐당 초당 최대 한 번과 미완료 표시 한 개로 제한합니다. 완료 값을 확인하는 전체 순회도 초당 최대 한 번 시작하며 기다리지 않습니다. 개별 드라이버 호출이 길어지면 각 큐의 조회 간격은 달라질 수 있습니다. 기존 전체 정리용 fence와 별개이고, 이 관측으로 자원을 해제하거나 FG를 끄지 않습니다.
   기록되는 지연은 Signal 호출 시작부터 CPU가 완료를 처음 관측할 때까지입니다. 폴링 간격과 CPU 지연이 포함되므로 순수 GPU 실행 시간·화면 FPS·메모리 페이지 교체 시간으로 읽으면 안 됩니다. 관측 실패와 장치 제거 값은 정상 완료로 처리하지 않습니다. FG 비활성화의 호출 이유와 SDK 결과도 함께 기록합니다.

3. 메모리 증가의 호출 위치와 자원 형태를 더 자세히 기록
   기존 `[GpuAlloc]`의 부분 관측을 유지하면서 생성 인자의 크기·형식·flags, 즉시 호출한 모듈과 RVA, 생성 후 경과 시간을 저장합니다. `[GpuAllocGroups]`와 `[GpuAllocGroup]`에는 현재 관측량이 큰 그룹과 이전 성공한 상세 표본보다 증가한 그룹을 제한된 수로 출력합니다. 첫 표본에는 증가 비교 기준이 없으며 실패한 표본은 기준을 바꾸지 않습니다.
   1MiB 이상인 관측 가능한 committed resource와 heap, 최대 4,096개 슬롯만 포함합니다. 작은 자원·알림 미지원·등록 실패·슬롯 부족은 누락 카운터로 구분합니다. 생성 후 오래 지났다는 사실은 미사용이나 누수를 뜻하지 않습니다. 추정 생성량은 GPU 상주량과 다르며, 호출 위치도 논리적인 자원 소유자를 확정하지 않습니다.
   게임 GPU 자원을 붙잡는 COM 참조는 남기지 않습니다. 파괴 콜백이 먼저 언로드되지 않도록 모드 DLL의 수명만 프로세스 종료까지 유지합니다. 상세 표본은 고정 작업 공간을 사용하고 정렬은 목록 잠금 밖에서 수행하지만, 복사 중 생성·파괴 관측이 잠깐 기다릴 수 있으므로 비용이 없는 기능은 아닙니다.

4. 압박이 시작되는 구간과 진단 비용을 기록
   `[LongSession]`에 메모리 압박 구간 번호와 경과 시간, 관측 구간의 사용량·예산 최솟값/최댓값, 관측한 큰 증가·감소와 표본 간격을 남깁니다. 압박 완화·정상화는 예산 대비 사용량 상태이며 게임 FPS 복구 판정이 아닙니다. 메모리는 약 1초 간격의 표본이므로 순간 최고치를 모두 포착하지는 못합니다.
   native Present의 CPU 평균·합계와 진단 표본·로그 처리·큐 관측의 CPU 비용을 분리합니다. 자원 Release의 목록 잠금 대기, 임시 참조와 native 호출, 마지막 native Release는 64회 중 한 번 측정합니다. 기존 참조 수와 잠금 순서는 바꾸지 않았습니다. 표본 최대치는 관측하지 못한 호출을 포함하지 않으며 실제 GPU 완료 시간도 아닙니다.
   정상 구간은 약 30초마다 기록하고, 압박·기존 끊김 상태 전환과 제한된 지연·메모리 변화 이벤트를 추가 기록합니다. 이 장시간 진단의 출력은 총 1,024줄로 제한하며 이후에도 메모리 내 관측은 계속합니다. 실제 GPU 환경에서 추가 관측의 성능 비용은 아직 측정하지 못했습니다.

## 유지 조건

- Intel XeFG 출력과 최대 6배 확장(원본 1장 + 보간 최대 5장)을 유지합니다. 설치 설정의 초기 선택은 기존과 같은 3배이며 자동 배수 감소는 없습니다.
- FFX 업스케일러, 업스케일 비율 1.5, FSR4 preset 1, 기존 약 152.7 FPS 제한, HDR·노출·색상·샤프닝과 pacing 설정을 유지합니다.
- Intel XeFG 1.3.1.78, XeLL 1.3.2.10 및 AMD 업스케일러 등 기존 구성 DLL을 유지합니다. 새로 빌드하는 모드 DLL은 `dxgi.dll`입니다.
- R6의 입력 형식 전환·새 입력에 근거한 제한적 FG 복구·FFX 컨텍스트 목록 동기화와 R5의 자원 수명 보호를 유지합니다. SDK의 보간 재개 상태는 게임 전체 FPS 복구를 증명하지 않습니다.
- DLSS5/NR와 추가 FG 모드 중첩은 포함하지 않습니다. DLSSG 입력 이름은 게임 정보를 받는 호환 경로이며 실제 출력은 Intel XeFG입니다.
- 강제 RAM 이전, 게임 자원 강제 해제, 상주 우선순위 조작, 고정 2.5GiB 회수는 구현하지 않았습니다. 해당 자원이 미사용이라는 근거 없이 적용하면 데이터 손상이나 더 큰 정지가 발생할 수 있습니다.
- UI fence 대기와 실제 전체 정리의 GPU 완료 확인에는 기존 최대 5초 제한이 남아 있습니다. R7의 새 진행 관측에는 대기 호출을 추가하지 않습니다.

최신 공식 OptiScaler 커밋 `80f4c61b51f4d54d7377f215799a20b716e8032f`도 확인했습니다. 이 변경은 Streamline의 기능 로드 호환 처리이며, 현재 경로의 메모리·큐 정체 수정 근거가 없어 채택하지 않았습니다. 최신 nightly·Coldwood donor·Intel 릴리스와 다른 모더의 공개 자료도 검토했으나 검증 가능한 새 Dogtown 전용 패치를 찾았다고 주장하지 않습니다. 채택·제외와 기존 수정 이력은 `UPSTREAM_REVIEW.json`에 기록합니다.

## 설치와 로그

게임을 완전히 종료한 뒤 기존 모드의 `dxgi.dll`이 있는 폴더에 설치 ZIP의 내용물을 덮어씁니다. Symbols ZIP은 충돌 분석용이며 설치할 필요가 없습니다.

로그는 `dxgi.dll`과 같은 폴더의 `OptiScaler-JaeYun-R7.log`입니다. 문제가 발생하면 게임을 다시 실행하기 전에 복사해 보관하십시오. 같은 저장 지점에서 Night City → Dogtown 이동을 비교하면 도움이 됩니다.

동봉 INI는 R6 배포 설정을 유지하고 로그 이름만 R7로 변경합니다. 직접 수정한 INI는 덮어쓰기 전에 보관하십시오. 할당 관측 자체의 영향을 비교하려면 INI에 다음 설정을 추가하고 게임을 완전히 재시작할 수 있습니다.

```ini
[Diagnostics]
GpuAllocationTracking=false
```

기본값은 `true`입니다. 이 값은 시작할 때 고정되며 게임 중 변경해도 적용되지 않습니다. `false`는 추가 할당 관측만 끕니다. Intel FG, 기존 자원 수명 추적과 GPU 큐 진행 관측은 유지합니다. 비교 후 원래 동작으로 돌아가려면 `true`로 변경하고 재시작하십시오.

## 검증 범위

실제 생산 함수·도우미를 사용하는 회귀 시험, 동시 실행과 실패 주입, 참조 수명·hook 설치/해제, 품질 설정·셰이더 보존 검사, Windows x64 Release 빌드와 패키지 검사가 검증 대상입니다. 정확한 실행 결과는 `TEST_RESULTS.json`, `BUILD.json`, `PACKAGE_AUDIT.json`, `QUALITY_REVIEW.json`, `INDEPENDENT_REVIEW.json`을 기준으로 확인하십시오. `SOURCE_EVIDENCE.zip`에는 소스와 검증 자료가 포함됩니다.

실제 Cyberpunk 2077/RX 9070 XT의 Dogtown 이동과 장시간 플레이는 이 환경에서 실행하지 못했습니다. 테스트 통과는 실제 게임의 메모리 증가나 FPS 회복을 보장하지 않습니다. 특히 게임·드라이버·provider의 내부 할당을 모두 관찰하는 기능은 아니므로 남은 원인은 새 로그로 구분해야 합니다.
