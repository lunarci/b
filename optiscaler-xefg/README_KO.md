# JaeYun XeFG6x R6

Night City에서 Dogtown으로 이동한 뒤 프레임 저하가 계속되는 R5 증상을 대상으로, 전환 후 입력 거부와 FG 복구 경로를 수정하고 메모리 증가의 출처를 구분하는 진단을 추가한 빌드입니다.

R5 로그에서는 LOCAL 메모리 사용량이 약 11,326MiB에서 15,850MiB로 늘어 OS 예산 약 14,128MiB를 넘었습니다. 같은 구간에 native Present의 CPU 소요 시간도 증가했습니다. 반면 미제출 명령은 누적되지 않았고, 기존 자체 복사 버퍼 카운터는 0이었습니다. 이 값만으로 게임·Intel provider·드라이버 중 누가 메모리를 늘렸는지, 실제 보간이 중단됐는지를 확정할 수는 없습니다.

## R5에서 달라진 점

1. 바뀐 입력 형식을 계속 거부하던 경로 수정
   HUD 없는 화면 입력의 형식이 한 번 바뀌면 이전 형식을 기억한 채 매 프레임 전환을 다시 요청할 수 있던 코드를 수정합니다. 형식 변화는 이력 전환으로 처리하며, 실패한 자원 태그가 준비된 입력으로 남지 않도록 정리합니다. 이 결함은 검토한 최신 OptiScaler 공식 소스에도 남아 있습니다. Dogtown에서 실제로 이 조건이 발생했는지는 R5 로그로 확인되지 않았습니다.

2. Intel API 실패와 정상 경고를 구분하고 새 입력으로 복구
   자원 전달 실패를 전역 FG 초기화 반복으로 연결하지 않습니다. 복구 가능한 오류에는 간격을 두고 재시도하고, 활성화 이후 새 프레임의 깊이·모션 벡터·필요한 HUD 없는 화면·상수를 다시 확인합니다. 비활성 상태에서 성공한 태그만으로 복구를 인정하지 않습니다.
   native Present 이후 Intel 상태가 보간 성공과 원본을 포함해 표시 큐로 보낸 장수 2장 이상을 보고해야 SDK의 프레임 생성 재개로 기록합니다. 화면에 실제 표시된 FPS를 독립적으로 측정한 값은 아닙니다. 원본 한 장, 이력 전환 경고, 테스트용 Present는 이 근거가 되지 않습니다. 지원되지 않는 장치·드라이버, 유효하지 않은 컨텍스트, 누락된 SDK 기능처럼 새 provider가 필요한 오류는 중단 이유를 기록합니다. 일반적인 장치 호출 실패·메모리 부족·변경 가능한 설정 오류는 간격을 둔 재시도 대상으로 남깁니다.

3. FFX 업스케일러의 컨텍스트 목록 동시 접근 수정
   이전 업스케일러는 지연 정리 스레드에서 파괴되고 새 업스케일러는 다른 스레드에서 만들어질 수 있습니다. 두 경로가 같은 컨텍스트 목록을 잠금 없이 수정하던 데이터 경쟁을 없앴습니다. 목록 조회·등록·제거만 짧게 잠그고 실제 provider 호출은 잠금 밖에서 실행합니다. 업스케일 연산과 화질 설정은 바꾸지 않습니다.

4. 실제 FG 출력과 메모리 증가를 구분하는 진단
   `[XeFGPresent]`에는 SDK 버전, native Present의 SDK 상태·표시 큐로 보낸 장수·오류, 활성화 상태와 복구 결과를 기록합니다. `[XeFGInputs]`에는 입력 종류별 태그 성공·경고·실패와 형식 변화 등을 기록합니다.
   `[GpuAlloc]`은 1MiB 이상인 관측 가능한 committed resource와 heap의 생성 호출 모듈별 할당·해제 추정치를 기록합니다. 최대 4,096개 고정 슬롯을 사용하고 파괴 알림을 관찰하며, 게임 자원을 붙잡는 COM 참조는 남기지 않습니다. 작은 할당, 지원하지 않는 알림, 등록 실패, 슬롯 부족은 별도 누락 카운터로 표시합니다.
   파괴 콜백의 코드가 먼저 언로드되지 않도록 모드 DLL의 수명만 프로세스 종료까지 유지합니다. 게임의 GPU 자원 수명을 연장하는 동작은 아닙니다. 이 관측 코드의 실제 GPU 환경 성능 비용은 아직 측정하지 못했습니다.
   이 통계는 부분적인 생성 호출 출처이며 실제 소유권이나 GPU 상주 메모리 총량이 아닙니다. placed resource를 heap과 중복 계산하지 않습니다. Intel이 보고하는 heap 요구량도 실제 상주량과 구분합니다. 기존 전체 VRAM 예산·native Present·작업 감시 진단은 유지합니다.

5. R5의 자원 수명 보호 유지
   논리적인 FG 전환에서 provider와 자체 자원을 보존하고, 실제 파괴에는 작업 완료를 확인하는 정책을 유지합니다. 공식 커밋 `349176128f5ce87fb81a4c636569c60c44557fec`에 따른 강제 Release 제거는 R5에서 이미 반영된 수정입니다. R6의 새 upstream 채택으로 중복 설명하지 않습니다.
   UI fence 대기와 실제 전체 정리의 GPU 완료 확인에는 기존 최대 5초 제한이 남아 있습니다. 새 진단 hook의 설치·해제도 트랜잭션 실패 시 기존 연결을 보존합니다.

## 유지 조건

- Intel XeFG 출력, 최대 6배(보간 5장 + 원본 1장) 확장 유지. 동봉 설정의 초기 선택은 기존과 같은 3배입니다.
- FFX 업스케일러, 업스케일 비율 1.5, FSR4 preset 1, 기존 약 152.7 FPS 제한 유지.
- 기존 HDR·노출·색상·샤프닝 설정과 모션·시간·이력 처리 보완, pacing 설정 유지.
- Intel XeFG 1.3.1.78, XeLL 1.3.2.10과 AMD 업스케일러 등 구성 DLL은 기존 payload를 유지합니다. 새로 빌드하는 모드 DLL은 dxgi.dll입니다.
- DLSS5/NR 및 추가 프레임 생성 모드 중첩은 적용하지 않습니다. DLSSG 입력 이름은 게임의 프레임 생성 정보를 받는 호환 경로이며 실제 출력은 Intel XeFG입니다.
- VRAM 압박을 이유로 업스케일 비율이나 최대 배수를 자동으로 낮추지 않습니다. 게임·드라이버 소유 자원의 강제 해제나 RAM 강제 이전은 수행하지 않습니다.

최신 OptiScaler master/nightly, Coldwood donor, Intel SDK 및 다른 모더의 공개 자료를 확인했습니다. 검토 시점의 공식·donor head는 R5 검토 당시와 같았고, 기존 Intel DLL에는 해당 최신 릴리스의 수정이 이미 포함되어 있습니다. 검증 가능한 새 Dogtown 전용 패치를 찾았다고 주장하지 않습니다. 정확한 커밋과 채택·제외 근거는 UPSTREAM_REVIEW.json에 기록합니다.

## 설치와 로그

게임을 완전히 종료한 뒤 기존 모드의 dxgi.dll이 있는 폴더에 설치 ZIP의 내용물을 덮어씁니다. Symbols ZIP은 충돌 분석용이며 설치할 필요가 없습니다.

로그는 dxgi.dll과 같은 폴더의 `OptiScaler-JaeYun-R6.log`입니다. 문제가 발생하면 게임을 다시 실행하기 전에 이 파일을 복사해 보관하십시오. 같은 경로의 Night City → Dogtown 이동이 중요한 비교 구간입니다.

동봉 INI는 기존 배포 설정을 유지하고 로그 파일명만 R6로 바꿉니다. 개인적으로 바꾼 INI가 있다면 덮어쓰기 전에 보관하십시오.

## 검증 범위와 한계

소스와 payload 보존 검사, 실제 구현을 사용하는 입력·복구·동시 실행 회귀 시험, FFX 목록 동시 접근 시험, COM 파괴 알림·실패 주입·hook 설치와 해제 시험, Windows x64 Release 빌드와 최종 패키지 검사가 검증 대상입니다. 정확한 수행 결과는 TEST_RESULTS.json, BUILD.json, PACKAGE_AUDIT.json을 기준으로 확인하십시오. SOURCE_EVIDENCE.zip에는 소스와 검증 자료가 포함됩니다.

실제 Cyberpunk 2077/RX 9070 XT에서 Dogtown 진입·장시간 플레이·프레임·화질을 이 빌드 환경에서 검증하지 못했습니다. 코드에서 확인한 복구 결함과 데이터 경쟁을 고쳤지만, R5의 전체 VRAM 증가가 이 결함에서 발생했다고 입증한 것은 아닙니다. SDK가 보간을 다시 시작했다는 진단도 게임 전체 FPS가 회복됐다는 뜻은 아닙니다.

메모리 압박이나 장치 오류가 계속되면 게임 재시작이 필요할 수 있습니다. 정상 복구로 표시하지 않고 실패 이유와 관측 한계를 로그에 남깁니다.
