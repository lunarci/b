# NR GPU 상태 보호 수정본

NR 처리 중 GPU의 조건부 실행 상태가 FSR에 잘못 전달될 수 있는 경로를 보호하는 수정본입니다. **Windows 검사는 코드 동작을 확인하는 검사이며, 재윤님의 실제 게임에서 흰색 깨짐과 잔상이 해결됐다는 의미는 아닙니다.**

## 설치

1. 게임과 MO2를 종료합니다.
2. 다운로드 폴더 등 원하는 새 폴더에 ZIP **전체를 압축 해제**합니다. 게임 폴더에 풀 필요는 없습니다.
3. 압축을 푼 폴더의 **01_APPLY_FIX.cmd**를 실행합니다. 기본 설치 대상은 **`C:\CYBERPUNK_ARK_PACK_MO2`**입니다.
4. 평소처럼 MO2에서 게임을 실행합니다.

01번은 기존 Matheus ASI와 설치 기록을 백업하고 수정 ASI를 적용합니다. 설치 기록이 없을 때도 지원하는 기존 ASI의 실제 해시를 확인합니다. 기존 INI 파일과 보정 강도, NR 입력 85%, 업스케일 비율, XeFG 활성·배율을 그대로 유지합니다. **Effect 0을 먼저 설정할 필요가 없으며, 설치기가 Effect 값을 0으로 강제하지 않습니다.**

다른 MO2 폴더를 사용한다면 첫 번째 인수로 지정합니다.

```bat
01_APPLY_FIX.cmd "D:\My MO2"
```

## 확인 및 되돌리기

- 같은 장면에서 팔 움직임, 흰색 깨짐, 잔상을 확인합니다.
- 게임과 MO2를 종료한 뒤 **03_COLLECT_LOGS.cmd**를 실행합니다. 이 압축 해제 폴더의 `Results`에 생성되는 `MOTION_EVIDENCE-….zip`을 전달합니다.
- 되돌릴 때는 **02_RESTORE_PREVIOUS.cmd**를 실행합니다. 다른 경로에 설치했다면 위와 같은 첫 번째 인수를 지정합니다.

기존 비교본에서 이어서 설치한 경우에는 그 비교본이 보관하던 최초 백업과 복원 관계를 이어받습니다. 따라서 02번은 단순히 직전 비교본으로 돌아가는 것이 아니라 기존 백업에 기록된 ASI·설치 기록까지 복원할 수 있습니다. 이전 비교본이 Effect 값을 변경하고 백업한 경우, 그 원래 Effect 복원도 유지됩니다. 이번 수정본만 새로 설치한 경우에는 Effect 값을 소유하거나 변경하지 않습니다. 사용자가 나중에 바꾼 다른 INI 설정은 보존합니다.

## 수정 범위

GPU에는 일부 명령의 실행 여부를 조건에 따라 결정하는 상태가 있습니다. 수정본은 이 상태가 해제돼 있다는 사실을 추적해서 확인한 경우에만 해당 명령 목록에서 NR을 실행합니다. NR 처리 후 원래 FSR로 넘기기 전에 해제 상태를 복구합니다.

조건이 활성화돼 있거나 현재 상태를 확인할 수 없는 명령에서는 **그 호출의 NR 처리를 건너뛰고 기존 FSR 호출을 그대로 수행**합니다. NR 전체를 항상 끄는 방식은 아닙니다. 활성 조건의 버퍼를 다시 지정하는 방식은 사용하지 않습니다. 같은 버퍼여도 GPU가 앞서 읽어 둔 조건과 현재 값이 달라질 수 있기 때문입니다.

기본 NR 0.3.0, 신경망 모델, OptiScaler, XeFG 실행 파일은 교체하지 않습니다. 보정 강도가 0이면 기존 원본 화면 전달 경로를 유지하고, 0보다 크면 보정 합성 경로를 사용합니다. 기존 입력 85%와 프레임 생성 설정을 유지하지만, 실제 프레임·지연시간·화질 결과는 게임에서 확인해야 합니다.

## 로그 해석

Effect 0에서 `original_color_stats`의 `passthrough`가 증가하고 `resolved=0`이면 원본 화면 전달 분기를 실행했다는 뜻입니다. 검사기는 이를 `ORIGINAL_COLOR_PASSTHROUGH_RECORDING_OBSERVED`로 구분합니다. GPU 결과나 화질이 정상이라는 판정은 아닙니다.

`predication_stats`의 `bypass_active`가 증가하면 실제 활성 조건을 감지하여 해당 호출의 NR을 건너뛴 것입니다. `admitted`만 증가하고 `bypass_active=0`이라면 그 실행에서는 활성 조건이 관찰되지 않았으므로, 이번에 확인한 코드 결함이 재윤님의 깨짐 원인이었다는 증거는 없습니다. `bypass_unknown`과 `bypass_untracked`는 상태를 확인할 수 없어 NR을 건너뛴 횟수입니다.

OptiScaler 로그가 현재 addon 실행보다 오래되면 `STALE_BEFORE_ADDON_SESSION`, 지정한 로그가 없으면 `CONFIGURED_LOG_MISSING`으로 표시합니다. 오래된 로그를 현재 XeFG 동작의 증거로 사용하지 않습니다.

Windows 빌드·검사 결과는 `evidence`, 파일 해시와 소스 커밋은 `BUILD_PROVENANCE.json`, 해당 빌드의 소스는 `SOURCE.zip`에 포함됩니다.
