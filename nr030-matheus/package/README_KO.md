# Matheus NR030 추가 모드 — 실험판 0.2.1 MapRecovery

**0.2.1 수정:** 맵 전환 후 이미 끝난 GPU 자원을 계속 붙잡을 수 있는 경로를 고쳤습니다. 전체 완료 슬롯 정리, 유휴 추가 버퍼 축소, VRAM·처리 상태 로그를 추가했습니다. 원인 검토와 맵 전후 비교 방법은 `MAP_RECOVERY_KO.md`에 있습니다. 실제 FPS 회복은 아직 실기에서 확인하지 않았습니다.

**이번 수정:** 기존 85% 입력 축소에 matiasLombo 방식의 원본 색 비율 보존과 Yuri 방식의 깊이 경계 보호를 통합했습니다. 기본값은 두 기능 모두 켬입니다. 비교·채택 범위는 `COMPARISON_KO.md`, 수정 소스는 `SOURCE.zip`에 있습니다. 실제 게임 화질 향상은 아직 검증되지 않았습니다.

**배포 형태와 실제 검증 범위부터 확인해 주세요.** 이 문서는 테스트 통과 증명이 아닙니다. 실제 완료한 검증과 미실시 항목은 동봉된 `BUILD_PROVENANCE.json`, `BUILD_STATUS_KO.md` 및 검증 결과를 기준으로 합니다. ASI가 없거나 manifest의 검증값이 false인 **소스 키트는 플레이용 설치본이 아니며, 아래 설치 명령도 차단됩니다.** Windows 빌드·WARP·Windows PowerShell 5.1 테스트는 해당 실행 결과에 통과가 명시된 경우에만 완료된 것입니다. Linux 교차 빌드나 PowerShell 7 실행은 이 Windows 검증을 대신하지 않습니다.

현재 사용 중인 **AMD NR 0.3.0 + OptiScaler + Intel XeFG 4X** 구성에 Matheus 방식의 입력 축소와 잔차 합성을 추가하는 실험판입니다. 게임 해상도·업스케일링 배율·XeFG 설정은 변경하지 않습니다.

기존 NR 엔진을 실행하기 전에 **NR에 들어가는 영상만 가로·세로 85%로 축소**하고, 처리 결과에서 원본 저해상도 영상과의 차이를 구해 기존 게임 입력 크기의 영상에 합성합니다. 그 뒤 기존 FSR 업스케일링과 XeFG 경로로 넘깁니다. 85%는 최종 FPS 향상률이나 화질 유지율을 뜻하지 않습니다. 축소·합성 자체의 비용도 있으므로 실제 이득은 같은 장소에서 비교해야 합니다.

이 패키지는 Matheus 원본 배포 DLL을 그대로 넣는 방식이 아닙니다. Matheus의 공개 셰이더를 기반으로 **재윤님 v1.4의 특정 NR 0.3.0 바이너리에 맞춘 별도 연결 모드**입니다. 원본의 구형 런타임용 주소를 그대로 사용하지 않습니다. 출처와 수정 범위는 동봉된 NOTICE 및 소스 저장소에서 확인할 수 있습니다.

**빌드·설치기·셰이더 검증과 실제 Radeon 게임 검증은 서로 다릅니다.** 실제 Cyberpunk 2077 / RX 9070 XT에서의 정상 화면, 안정성, FPS 개선은 아직 검증되지 않았습니다. 설치 성공이나 로그 생성만으로 효과가 입증되지는 않습니다. 추가 GPU 버퍼도 필요하므로 기존 VRAM 사용량이 높은 상태에서의 안정성은 첫 게임 실행에서 확인해야 합니다.

## 설치

1. ZIP 파일의 속성에 **차단 해제**가 있으면 적용한 다음, 일반 폴더에 전체 압축을 풉니다. ZIP 안에서 CMD를 직접 실행하지 않습니다.
2. Cyberpunk 2077과 MO2를 종료합니다.
3. `01_INSTALL_ADDON.cmd`를 실행합니다.
4. 완료 메시지를 확인하고 평소처럼 MO2에서 게임을 실행합니다.

설치 대상은 다음 한 곳입니다.

`C:\CYBERPUNK_ARK_PACK_MO2\mods\ARK_OptiScaler_\Root\bin\x64\plugins`

추가되는 게임용 파일은 `MatheusNR030.asi`, `MatheusNR030.ini` 두 개입니다. 추가 모드가 실행되면 같은 폴더에 `MatheusNR030.log`를 기록합니다. MO2 실행 중 생성된 로그는 `overwrite\Root\bin\x64\plugins`에 보일 수도 있습니다.

설치기는 기존 NR ASI의 SHA-256, v1.4 설치 기록, DLSS 입력→FFX 업스케일러와 XeFG 4X 설정을 먼저 확인합니다. 다르면 파일을 교체하거나 설정을 자동 수정하지 않고 이유를 표시하며 중단합니다. 기존 NR·모델·OptiScaler·Intel 파일 및 관련 INI는 설치 전후 해시로 보존 여부를 확인합니다.

## 첫 비교 방법

이번 기능만 비교하려면 `ScalePercent=85`를 유지하고 `ColourPreservationPercent=0`, `DepthProtection=0`, `EffectPercent=100`으로 바꾸면 이전 0.1.0의 합성 계산으로 돌아갑니다. 새 기본값은 각각 `100`, `1`, `100`입니다. `EffectPercent`는 최종 보정 강도(0~100)이며, 0으로 두어도 NR 연산은 계속됩니다. 게임 재실행 후 적용됩니다.

1. 같은 저장 위치와 동일한 그래픽 설정에서 실험판 기본값 `ScalePercent=85`로 확인합니다.
2. 게임을 종료하고 설치된 `MatheusNR030.ini`의 `[MatheusNR030]`에서 `ScalePercent=100`으로 바꿉니다. 100은 축소·추가 합성을 끄고 기존 NR 처리를 그대로 사용합니다.
3. 같은 저장 위치를 다시 불러와 FPS, 입력 반응, 얼굴·문자·윤곽의 변화와 잔상을 비교합니다. 두 실행에서 해상도나 XeFG 배율을 함께 바꾸지 않습니다.
4. 더 낮은 NR 입력을 비교할 때만 `ScalePercent=75`를 사용합니다. 허용 값은 75, 85, 100입니다. 설정 변경은 게임 재실행 후 적용됩니다.

`Enabled=0`으로 두면 추가 모드를 비활성화합니다. 기본 NR 자체를 끄는 설정은 아닙니다. 화면 이상이나 반복 충돌이 있으면 아래 제거 명령으로 추가 모드만 되돌린 뒤 기존 구성을 확인합니다.

현재 실험판은 실행 중 NR 입력 크기나 FFX 처리 문맥을 다시 만드는 경우까지 지원하지 않습니다. 축소 NR이 한 번 초기화된 뒤 해상도·처리 문맥이 바뀌거나 추가 경로를 적용할 수 없으면, 해당 호출은 **NR을 생략하고 원래 크기의 입력을 FSR에 넘깁니다.** 교착을 피하기 위한 우회이며, 기존 NR이 계속 작동했다고 해석하면 안 됩니다. 다시 시도할 때는 게임을 완전히 종료한 뒤 실행합니다.

## 실행 기록 확인

게임을 실행해 실제 장면을 확인한 뒤 `03_CHECK_ADDON.cmd`를 실행합니다. 결과는 이 압축파일을 푼 폴더의 `Results\MATHEUS_CHECK.txt`에 저장됩니다. 게임을 종료한 뒤 검사해도 됩니다.

검사는 최근 로그의 마지막 세션을 읽으며, 추가 모드 설치 이전 실행 기록을 새 실행의 성공으로 취급하지 않습니다.

| 표시 | 뜻 |
|---|---|
| `hook_active` | 지정 NR 바이너리의 연결 지점에 추가 모드가 연결됨 |
| `resolve_config` | 색 보존·깊이 보호·효과 강도 설정. 이 줄만으로 실행 완료를 뜻하지 않음 |
| `adapter_ready` | 원래 입력과 NR 입력의 실제 할당 크기. 예: 1920×1080 → 1632×918이면 각 축 85% |
| `CompositeRecordingObserved` | 해당 세션의 설정과 합성 명령 기록을 관찰함. 화질·추론 성공 판정은 아님 |
| `nr_recorded` | NR 결과를 사용하는 경로가 관찰됨. 기록된 명령 수이며 화면 품질 판정은 아님 |
| `resolved` | Matheus 잔차 합성 GPU 명령이 게임 명령 목록에 기록됨 |
| `gpu_completed` | 합성 명령을 기록한 슬롯이 GPU fence 완료 후 회수됨. NR skip만 발생한 슬롯은 포함하지 않으며, NR 모델 추론의 성공 판정은 아님 |
| `fallback` | 추가 경로를 적용하지 못한 호출 수. 축소 NR 초기화 이후에는 NR을 생략하고 FSR로 넘기는 경우도 포함 |
| `BASELINE_100_PERCENT` | 100% 비교 설정으로 기존 NR 처리를 사용함 |

`nr_recorded=0` 또는 `resolved=0`이면 추가 처리 성공으로 표시하지 않습니다. GPU 명령 기록과 GPU 완료도 분리해서 표시합니다. 실제 XeFG 4X 동작, 화질, 장시간 안정성, 성능 향상은 별도로 확인해야 합니다. 결과를 전달할 때는 `MATHEUS_CHECK.txt`와 게임 종료 직후의 `MatheusNR030.log`, `dlssnr_on_amd.log`, `OptiScaler.log`를 함께 보내면 됩니다.

## 추가 모드만 제거

게임과 MO2를 종료하고 **`02_REMOVE_ADDON.cmd`**를 실행합니다. 이 패키지가 설치한 ASI·INI와 소유권 기록만 제거합니다. 기존 NR 0.3.0, OptiScaler, XeFG와 해상도 설정은 유지됩니다.

백업·작업 기록은 `C:\CYBERPUNK_ARK_PACK_MO2\Matheus_NR030_Addon_Backup`에 저장됩니다. 직접 조정한 추가 모드 INI는 제거 전에 `ARK-MatheusNR030.ini` 등의 이름으로 보관하고 위치를 표시합니다. 추가 ASI 자체가 변경됐다면 다른 파일을 잘못 제거하지 않도록 작업을 중단합니다. 설정을 조정한 상태에서 다시 설치하는 경우도 기존 조정값을 자동 덮어쓰지 않습니다.

**기존 v1.4의 제거 명령은 기본 NR까지 제거하므로, 이 추가 모드만 되돌릴 때 사용하지 않습니다.**

## 개발·검증 기록

빌드 산출물에 포함된 `package-manifest.json`은 소스 커밋, 빌드 실행, 정적 ABI 확인 근거 및 ASI·INI 해시를 기록합니다. `game_runtime_verified=false`는 실제 게임 검증 전 상태를 뜻합니다. 정적 ABI 확인은 특정 바이너리의 함수·구조가 분석한 내용과 일치한다는 뜻이며 AMD GPU에서 실행했다는 뜻이 아닙니다.

저장소의 **소스 폴더**에는 빌드 산출물 ASI가 없고 manifest의 `build_verified`·`abi_verified`도 false로 유지됩니다. 이 소스 폴더 자체는 설치 패키지가 아닙니다. 검증을 통과한 빌드에서만 payload와 검증 기록을 채운 별도 ZIP을 생성합니다. 값을 수동으로 바꿔 설치를 우회하지 않습니다.

설치기 테스트는 Windows PowerShell 5.1에서 `powershell.exe -NoProfile -File .\Test-Package.ps1`로 실행합니다. 독립 임시폴더의 합성 파일로 설치·재설치·롤백·제거·설정 보존·로그 오판 방지를 확인하며, 실제 게임이나 NR 모델은 실행하지 않습니다. 결과는 `test-results\installer-tests.json`에 기록됩니다.
